## Arranque local
En Windows con Docker Desktop: `./scripts/local.ps1 Start`. En este equipo con Docker Toolbox: `./scripts/local.ps1 Start -Toolbox`.

El script conserva `.env` si ya existe; si falta, genera contraseñas y token aleatorios sin mostrarlos. Recupera Compose 2.39.4 con checksum oficial al usar Toolbox, crea túneles solo en loopback y arranca los servicios. Alembic aplica las migraciones y crea las categorías; **no ejecutar el SQL manual**. También crea una cuenta administradora local si aún no existe.

Accesos: [blog](http://localhost:3000), [cuenta](http://localhost:3000/cuenta), [panel](http://localhost:3000/editorial), [moderación](http://localhost:3000/moderacion), [API](http://localhost:8000/docs) y [correo local](http://localhost:8025).

La cuenta inicial usa `BOOTSTRAP_EMAIL` (por defecto `editor@localhost.test`) y la contraseña local `EDITORIAL_PASSWORD` de `.env`. No se muestra ni se envía al navegador como configuración. Es una cuenta de administración local, no un usuario de la comunidad inventado. Una cuenta existente nunca se modifica al repetir el arranque.

En otros sistemas: configurar `.env` desde el ejemplo, fijar contraseña de PostgreSQL/URL, `EDITORIAL_API_TOKEN` y `EDITORIAL_PASSWORD` aleatorios; ejecutar `docker compose up --build -d` y `docker compose exec api python -m app.manage bootstrap`. Los contenedores deben estar saludables antes del segundo comando.

Pruebas: `./scripts/local.ps1 Tests -Toolbox` o `./scripts/local.ps1 Browser -Toolbox`. Parar sin borrar datos: `./scripts/local.ps1 Stop -Toolbox`. Con Docker Desktop omitir `-Toolbox`. Ver [prueba local](docs/LOCAL_TEST.md) y [cuentas y operación](docs/ACCOUNTS.md).
