## SEO y navegación implementados

- `/actualidad`, `/herramientas`, `/programacion`, `/tutoriales`, `/foro`. El middleware redirige permanentemente las secciones antiguas y conserva la query de paginación. Las anclas para saltar al contenido siguen siendo correctas para accesibilidad; no representan páginas duplicadas.
- Se conserva la URL de cada artículo publicado. No se inventan redirecciones de slugs ni se cambia la taxonomía existente.
- `/sitemap.xml` pasa a ser un índice: `/sitemap-pages.xml` y `/sitemaps/articles/N`, `/sitemaps/topics/N`, con XML válido y máximo 5.000 entradas por archivo. El sufijo `.xml` no es necesario cuando el tipo es XML. Solo contenido publicado y secciones/categorías con contenido; no búsqueda, paneles, cuentas ni textos legales pendientes. Las páginas paginadas son rastreables desde los enlaces y tienen canonical propio.
- El endpoint antiguo `/articles-sitemap` se conserva para compatibilidad con el frontend anterior durante actualización/rollback; el nuevo frontend usa lecturas acotadas `/seo/inventory` y `/seo/entries`. El proxy web no expone estas rutas de infraestructura.
- `robots.txt` permite rastreo y anuncia el índice. No se bloquea el rastreo de páginas privadas para que Google pueda ver noindex, 401 o redirección; robots no es control de acceso.
- Metadatos únicos por sección/página, marca coherente, Open Graph global y por sección/artículo, imagen PNG local. Los datos estructurados siguen serializados con escape de `<`, `>` y `&`.
- Las ilustraciones son propias, genéricas por sección y se identifican como tales; no representan una herramienta probada ni fotografías de noticias. No se afirma que una imagen genérica vaya a conseguir resultados enriquecidos.

## Rendimiento y diseño

Cabecera compacta conservando papel, tinta y acento editorial. Portada solicita hasta 12 artículos reales (no rellena con contenido inventado). Imágenes SVG de unos 740 bytes para lectura y PNG de 25–30 KB para compartir; dimensiones explícitas 1200×630, decodificación asíncrona y carga diferida de la ilustración bajo la cabecera del artículo. Recursos locales sin nuevas fuentes externas. Imágenes con caché de un día; contenido editorial sin caché compartida para mantener retirada inmediata. Nuxt sirve sus recursos de compilación con nombres hash.

Una muestra de laboratorio móvil en Chromium: viewport 390×844, CPU ×4, latencia añadida 150 ms, descarga 200.000 B/s y subida 100.000 B/s. Portada del entorno de prueba: LCP 2.320 ms, CLS 0, TTFB ~480 ms, cabecera ~193 px. Son observaciones de una ejecución, no una puntuación Lighthouse ni una garantía de Core Web Vitals. No hay medición de INP de campo ni comparación antes/después bajo idénticas condiciones. Se necesitan datos reales de Search Console/CrUX para evaluar el percentil 75.

## Seguridad y dependencias

- Permisos editor/admin, sesión verificada, CSRF en escrituras, límites Redis, Argon2 y comentarios moderados ya existen y pasan pruebas de regresión. No se ha habilitado registro ni correo.
- FastAPI no habilita CORS permisivo: el navegador usa el proxy del mismo origen; Origin/CSRF se comprueban en servidor. Entradas Pydantic con tamaños y slugs acotados; SQLAlchemy parametriza consultas. Límite añadido al offset del foro.
- PostgreSQL y Redis de producción no publican puertos. Solo Caddy publica 80/443. Entorno de prueba con proyecto Compose, volumen, usuarios y secretos propios; solo su Nuxt se publica en 127.0.0.1:13001. No contiene la clave OpenAI ni replica cuentas reales.
- Backups: timer diario y monitor activos, ejecución del backup del 23/10 registrada; las restauraciones aisladas anteriores están en VALIDATION.md. No se ha repetido una restauración completa en este bloque ni se acredita recuperación nueva de 0005 por ello. No hay migraciones nuevas en este bloque. Siguen pendientes réplica externa automática, retención operativa y alertas externas.
- pip-audit con requirements/constraints actuales: sin avisos conocidos. npm audit completo: 11 paquetes high afectados por dos avisos raíz, braces y node-forge; ambos sin versión corregida en los avisos consultados. No se ejecuta npm audit fix --force ni se rebaja Nuxt a 4.1.3 por una propuesta automática. No se han identificado esos paquetes en la imagen final de ejecución; la cadena de compilación continúa afectada y debe usar entradas controladas. Esto no equivale a una auditoría de seguridad exhaustiva.
- HSTS y CSP se han validado en Caddy aislado. CSP es Report-Only y permite inline para compatibilidad de hidratación; no se presenta como una CSP de bloqueo definitiva. No hay colector externo de reportes.

## Search Console, GA4 y AdSense: pasos manuales

1. Crear propiedad de prefijo `https://foroiaaldia.com/` en Search Console y elegir etiqueta HTML. Copiar solo el contenido en `GOOGLE_SITE_VERIFICATION` de production.env; Compose lo transmite a `NUXT_PUBLIC_GOOGLE_SITE_VERIFICATION`. No es necesario tocar DNS para este método. Comprobar la etiqueta en HTML sin sesión, pulsar Verificar y enviar `/sitemap.xml`. No hay verificación ni envío de sitemap realizados desde este entorno.
2. Completar datos reales autorizados del titular y revisar legal/privacidad/cookies. Nunca usar la marca como identidad jurídica ni reutilizar datos de factura sin autorización. SMTP sigue siendo necesario antes de abrir registro.
3. Crear el flujo web GA4 y definir conservación, transferencias y configuración. Desactivar medición mejorada automática en GA4 para que no capture consultas, formularios o enlaces no previstos. Usar conservación mínima adecuada y revisar Google Signals/publicidad (el código los desactiva). Completar la información legal correspondiente.
4. Configurar `GA4_ID` y después `ANALYTICS_ENABLED=true`, solo tras lo anterior. Por defecto está false; además se exigen ID válido y datos legales presentes. Modo básico: no descarga de gtag ni pings antes de aceptación. Rechazo y aceptación con igual estilo, elección local de hasta 180 días, retirada accesible. Cookies GA limitadas a 180 días y se intentan eliminar al retirar; una retirada recarga para detener el tag. No se envían query, hash, referente ni datos de formularios/cuentas; páginas de cuenta/panel se excluyen de los eventos propios. La medición mejorada debe desactivarse también en el servicio; la preparación de código no sustituye esa configuración.
5. Mantener AdSense sin scripts hasta aprobar la plataforma, completar requisitos y contar con una CMP certificada adecuada para la audiencia. El componente GA4 **no es** una CMP TCF de AdSense. La cuenta y la aprobación siguen pendientes. Cuando proceda, copiar el ID real `pub-...` a `ADSENSE_PUBLISHER_ID`; ads.txt aparecerá con la entrada estándar. Sin ID devuelve 404, sin vendedores inventados. No se ha añadido un ID real ni se han cargado anuncios. Evaluar ubicaciones limitadas bajo contenido, dimensiones estables y medición de CLS antes de añadir espacios publicitarios.
